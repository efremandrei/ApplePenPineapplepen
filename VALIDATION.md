# v0.4.0 verification

The shipped APK is built with installed Android SDK tools. GitHub Actions independently runs Gradle tests, lint, APK assembly, and an Android 16 emulator smoke test.

Local verification:

- 74 JUnit tests cover the scanner, protocol/TLS fixtures, credential handling, reporting and the new CVE applicability logic.
- Applicability tests cover numeric release ordering, all four range boundaries, exact versions, unsupported and contradictory ranges, OpenSSH portable updates, AND/OR configurations, unknown environment facts, vulnerable=false prerequisites, edition/platform constraints, negation, unsupported shapes and product-name syntax, newer affected-source data, parser/evaluation bounds, preservation of matching evidence under truncation, generic dictionary selection, deprecation/result-count checks, exclusion audit trails, duplicate/rejected CVEs, structured exports, comparison changes, and multi-port metadata propagation.
- Synthetic reports generated by original v0.1/v0.2/v0.3 classes verify deserialization and preservation of old scanner versions. Legacy CVE findings acquire no invented assessment.
- Java/API 36 compilation, AAPT2 resource/manifest compilation, D8 for API 30+, APK alignment, and signing checks are performed by the SDK build.
- The APK uses version code 4, keeps the original signing certificate, and disables debugging.

Unit tests use owned loopback fixtures. The final emulator suite verifies input values and enforces the owned fixture IP before starting each scan. NVD behavior is tested with deterministic source fixtures; live NVD availability is not a release gate. Optional lookups continue to use verified HTTPS, opt-in software-identifier sharing, response/rate/page limits, and a 24-hour cache.

The emulator seeds a v0.3 report, installs v0.4 as an update, checks retained history, scans owned HTTP/TLS/Redis/PostgreSQL/SMTP fixtures, verifies TLS probes and credential blocking/clearing, and exercises rescan and PDF/HTML/JSON exports with schema 4. Native smoke CVE lookup is off; applicability logic and CVE metadata are verified by JVM fixtures. The workflow's actual result is authoritative. Screenshots, exports, UI XML and logcat are retained as artifacts.

Physical-device power management and manufacturer-specific document providers remain unverified. The development-signed universal APK's checksum is in downloads/SHA256SUMS. CVE findings remain low-confidence candidates; installed packages, vendor backports, unsupported applicability formats and exploitability require separate verification.
